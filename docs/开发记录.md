# 家里两台机器三种 AI 服务怎么切？给 V100 主机做个"大模型切换"飞牛应用（全流程+踩坑记录）

## 前言

家里有两台机器协同干活：

- **飞牛 NAS**：日常存储 + 跑各种应用
- **Ubuntu 主机（192.168.50.10）**：双 Tesla V100-SXM2-16GB（V100 Duo），上面跑着三种抢 GPU 的 AI 服务：
  - **NInfer**（自研 C++/CUDA 推理引擎）— Qwen3.8-27B 对话，`:8080`
  - **ComfyUI** — Wan2.2 视频生成，`:8188`
  - **vLLM** — Qwen3-30B-A3B，`:8000`

矛盾很明显：**三张牌只有一桌牌**——两块 V100 16GB 显存，NInfer 加载就要占掉 ~13.4GB/卡，ComfyUI 出视频同样要占满。每次切换都得 SSH 上去敲一堆 `systemctl stop/start`，还经常忘掉对家服务，搞得两个服务抢显存一起崩。

于是分两步走：

1. 先在主机上写一个 **`ai-mode.sh` 切换脚本**（llm / video / vllm / off / status）
2. 再按飞牛应用规范把它包装成 **NAS 应用「大模型切换」**，应用中心点开 Web 面板一键切，顺便解决"主机休眠了叫不醒"的问题（WOL 唤醒）

**最终效果**：飞牛桌面点开「大模型切换」，看到主机在线状态、双 V100 显存占用、四个模式卡片点一下就切；主机休眠了还能一键 WOL 唤醒。实测 LLM↔视频来回切换 40 秒内完成服务交接。

## 一、先理清主机上的服务关系

### 1.1 三个 systemd 服务

```bash
$ systemctl list-units --type=service --state=running | grep -E 'ninfer|vllm|comfyui'
ninfer.service    NInfer V100 Duo - Qwen3.8-27B-nvfp4 engine server
vllm.service      vLLM OpenAI-compatible API server (Qwen3-30B-A3B)
comfyui.service   ComfyUI (port 8188)
```

三个服务都是 `systemctl enable` 的开机自启，所以一开机就会三方乱抢——这是switching要解决的第一个乱象。

### 1.2 自动休眠的"友军伤害"

之前给主机做过 `auto-power`（空闲自动休眠 + WOL 唤醒，已写成另一篇飞牛应用文章）。它的 `auto-power-idle.timer` 每 5 分钟跑一次 idlecheck，**但 idlecheck 只认本地活动，不认 SSH 会话**——于是我在 NAS 上通过 SSH 连着主机干活的时候，主机照样觉得"没人用"，直接休眠。生成视频跑到一半机器没了，排查了好久才发现（`journalctl -b -1` 里明明白白写着 `Performing sleep operation 'hibernate'`）。

**教训**：任何远程管理工具，切换到"工作模式"时必须顺带把休眠计时器停掉，活干完了（`off` 模式）再恢复。

## 二、主机侧：ai-mode.sh 切换脚本

### 2.1 设计：四种模式 + 状态

```bash
ai-mode llm     # NInfer 对话 (:8080)，停 comfyui/vllm
ai-mode video   # ComfyUI 视频 (:8188)，停 ninfer/vllm
ai-mode vllm    # vLLM (:8000)
ai-mode off     # 全停，恢复自动休眠
ai-mode status  # 看状态（纯文本 / --json）
```

核心逻辑就三条：
1. 切换前先 `keep_awake`（停掉三个 auto-power 计时器）
2. 停对家服务 → 等 2 秒 → 起目标服务（`off` 模式相反，还要 `allow_sleep`）
3. 状态支持 JSON 输出，给 NAS 上的 app 吃

### 2.2 关键代码

```bash
AP_TIMERS="auto-power-idle.timer auto-power-hibtest.timer auto-power-off.timer"

# 获取免密 sudo: 只允许特定的 systemctl 调用
need_sudo() {
  if [ -z "$(sudo -n systemctl is-active ninfer 2>/dev/null)" ]; then
    echo '错误: 免密 sudo 未生效 (检查 /etc/sudoers.d/ai-mode)' >&2; exit 1
  fi
}

keep_awake()  { svc stop $AP_TIMERS; }
allow_sleep() { svc start $AP_TIMERS; }

mode_llm()   { keep_awake; svc stop comfyui vllm; svc stop ninfer; sleep 2; svc start ninfer; }
mode_video() { keep_awake; svc stop vllm ninfer; svc stop comfyui; sleep 2; svc start comfyui; }
mode_vllm()  { keep_awake; svc stop comfyui ninfer; svc stop vllm; wait_gpu_free; svc start vllm; }
mode_off()   { svc stop comfyui ninfer vllm; allow_sleep; }
```

`status --json` 输出长这样（NAS app 直接解析）：

```json
{"mode":"video","uptime":"15688.25","services":{"ninfer":"inactive","vllm":"failed","comfyui":"active"},
 "auto_power":{"idle":"inactive","hibtest":"inactive","off":"inactive"},
 "gpus":[{"index":0,"name":"TeslaV100-SXM2-16GB","mem_used":480,"mem_total":16384,"util":0}, ...],
 "endpoints":{"ninfer":false,"comfyui":true,"vllm":false}}
```

### 2.3 免密 sudo：照抄 Aria2 的生命周期脚本模式

切换要 `systemctl start/stop`，而生命周期脚本/App 用户不能老要密码。配一个最小权限的 sudoers：

```bash
# /etc/sudoers.d/ai-mode  (chmod 440)
guoxizheng ALL=(root) NOPASSWD: /bin/systemctl start ninfer, /bin/systemctl stop ninfer, \
  /bin/systemctl start vllm, /bin/systemctl stop vllm, \
  /bin/systemctl start comfyui, /bin/systemctl stop comfyui, \
  /bin/systemctl is-active ninfer, /bin/systemctl is-active vllm, /bin/systemctl is-active comfyui, \
  /bin/systemctl stop auto-power-idle.timer, /bin/systemctl start auto-power-idle.timer, \
  ... (auto-power-hibtest.timer / auto-power-off.timer 同理)
```

### 3.3 后端 ai-switchd（Python 标准库）

三个核心能力：

**1. SSH 执行远程命令**（sshpass 免交互）

```python
def ssh_exec(cmd, timeout=25):
    env = dict(os.environ)
    env["SSHPASS"] = CONFIG.get("ssh_pass", "")
    full = ["sshpass", "-e", "ssh", "-T",
            "-o", "StrictHostKeyChecking=no",
            "-o", "UserKnownHostsFile=/dev/null",
            "-o", "ConnectTimeout=8",
            f"{CONFIG['ssh_user']}@{CONFIG['ssh_host']}", cmd]
    p = subprocess.run(full, capture_output=True, timeout=timeout, env=env)
    return p.returncode, p.stdout.decode().strip(), p.stderr.decode().strip()
```

**2. WOL 魔法包**（广播 + 单播，端口 7/9）

```python
def send_wol():
    mac = bytes.fromhex(CONFIG["wol_mac"].replace(":", ""))
    pkt = b"\xff" * 6 + mac * 16
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    s.setsockopt(socket.SOL_SOCKET, socket.SO_BROADCAST, 1)
    for dst in (CONFIG["wol_broadcast"], CONFIG["ssh_host"]):
        for port in (7, 9):
            for _ in range(3):
                s.sendto(pkt, (dst, port)); time.sleep(0.02)
```

**3. 后台 15 秒轮询线程**，持续刷新状态缓存，前端只需读 `/api/status`。

HTTP API 一览：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/status` | 主机状态 + 当前模式 + GPU + 服务 + 端点 |
| POST | `/api/switch` | 切换模式，body `{"mode": "llm\|video\|vllm\|off"}` |
| POST | `/api/wol` | 发 WOL 魔法包 |
| GET | `/api/log` | 操作日志 |
| GET | `/`、`/images/*` | 前端静态文件 |

### 3.4 前端（单文件 HTML）

纯原生 HTML/CSS/JS，无框架：
- **四个模式卡片**：当前模式绿色高亮 + 一键切换按钮
- **GPU 显存条**：双 V100 的 mem_total/mem_used/利用率
- **服务明细**：三个 systemd 服务 + 三个休眠计时器 + 三个 HTTP 端点探活
- **操作日志**：终端风格
- 10 秒自动刷新；切换中按钮禁用防抖

## 四、踩坑记录（本文精华）

### 坑 1：sudoers 里的多参数 systemctl 不匹配（最隐蔽）

第一版图省事：

```bash
svc() { sudo systemctl "$@"; }           # 一次传两个服务
svc stop comfyui vllm                     # = sudo systemctl stop comfyui vllm
```

结果 **ComfyUI 根本没被停掉**，NInfer 起来后两个服务抢同一块卡。原因：sudoers 的命令匹配是**精确字符串匹配**，`systemctl stop comfyui vllm`（两个参数）不匹配 `systemctl stop comfyui`（一个参数）这条规则，sudo 直接拒绝，而 `2>/dev/null` 把报错吃了，表面上"切换成功"。

**修复**：逐个服务调用：

```bash
svc() {
  local cmd=$1; shift
  for u in "$@"; do
    sudo systemctl "$cmd" "$u" 2>/dev/null || echo "警告: systemctl $cmd $u 失败" >&2
  done
}
```

### 坑 2：`sudo -n true` 检测免密 sudo 永远失败

脚本里自检免密 sudo 用了 `sudo -n true`，但 sudoers 白名单里**没有 `/bin/true`**，所以 `sudo -n true` 每次都失败，脚本直接退出。

**修复**：用白名单里的命令做探针：

```bash
[ -z "$(sudo -n systemctl is-active ninfer 2>/dev/null)" ] && echo "免密 sudo 未生效"
```

### 坑 3：休眠计时器"背刺"（现象：机器做着事突然掉线）

症状：SSH 操作到一半主机 `No route to host`，三个端口全闭。以为是电源/网络故障，`journalctl -b -1` 一看：

```
11月 10 11:47:38 systemd-sleep[47527]: Performing sleep operation 'hibernate'...
```

是自己装的 auto-power idlecheck 干的（只认本地活动，不管 SSH 会话）。

**修复**：模式切换时强制 `keep_awake` 停掉三个计时器；`off` 模式负责 `allow_sleep` 恢复节能。

### 坑 4：`pkill -f` 匹配到自己的 shell

写调度脚本时 `pkill -f model-convertd` —— **pkill -f 按完整命令行匹配，会把包含该字符串的当前 bash 一起杀掉**（exit code 143，命令莫名中断）。

**修复**：用 `$` 锚定匹配结尾，或换 `pgrep` 先查 PID 再按 PID kill：

```bash
pkill -f "python3 ai-switch/app/ai-switchd$"   # $ 锚定, 不匹配中间含该串的 shell
```

### 坑 5：SSH 里 `~` 被单引号包住不展开

```bash
ssh user@host "base64 -d > '~/ComfyUI/user/default/workflows/x.json'"
# 文件会真的写进名为 ~ 的目录里！
```

**修复**：远程命令里用 `$HOME` 或者不要给 `~` 加引号。

### 坑 6：应用进程随 bash 调用一起被杀

本地测试后端用 `nohup python3 ai-switchd &` 启动后，**下一次 bash 调用里进程已不在**（沙箱调用结束时会回收进程组）。排查了好一会才发现不是后端崩溃。

**修复**：凡是要跨调用存活的本地测试，整个流程（启动+请求+验证）放在**同一个 bash 调用**里完成；真正部署后由 systemd 托管，没有这个问题。

### 坑 7：飞牛生命周期脚本的祖传问题（沿用前一篇的教训）

- `cmd/main` 里显式 `export PATH` + 命令绝对路径（PATH 几乎是空的）
- 参照 Aria2 的成熟写法：`bash -c "${CMD}" &` + 立即写 pid + 不 sleep 不检查
- `install_callback` 里写配置全部 try/except，绝不阻断安装
- 涉及多版本的格式：`manifest` 键值对用空格对齐（`key` 补齐到 16 列）

## 五、验证测试

### 5.1 切换时序（真机实测）

```
[video → llm]  click 切换
  → 停 vllm/ninfer/comfyui, 停休眠计时器
  → systemctl start ninfer
  → ~40s 后 NInfer :8080/health 返回 {"model":"qwen3.8-27b","status":"ok"} ✅

[llm → video]  click 切换
  → 停 ninfer, 等 2s
  → systemctl start comfyui
  → ~15s 后 :8188/system_stats 200 ✅
```

NInfer 慢是因为 27B 权重要从硬盘加载进显存；ComfyUI 本身轻量，快很多。

### 5.2 状态正确性

`~/ai-mode.sh --json` 的 mode 字段由服务状态推导（ninfer active → llm，comfyui active → video，vllm active → vllm，否则 off），前端据此高亮当前卡片，杜绝"UI 说切了但服务没动"。

### 5.3 边界情况

- 主机休眠时 SSH 失败 → 前端显示"主机离线" + WOL 按钮 → 唤醒后 15 秒内轮询恢复在线
- SSH 密码没配 → switch 直接报错而非超时
- 切换中（switching 状态）→ 所有按钮禁用，完成后自动恢复

## 七、总结

### 飞牛应用开发 checklist（合并两篇的经验）

1. ✅ `fnpack create` 建项目（native 模板），`fnpack build` 出 fpk
2. ✅ manifest 配端口 + `ctl_stop` + 桌面入口（`desktop_uidir`/`desktop_applaunchname`）
3. ✅ `config/privilege` 用 package 专用用户
4. ✅ `cmd/main` **照抄 Aria2**（别自己发明）: PATH、`bash -c &`、写 pid
5. ✅ sudoers 最小权限白名单（**注意命令参数必须逐字匹配**）
6. ✅ 向导收集敏感配置（SSH 密码），`install_callback` 写入 `etc/`
7. ✅ 后端纯标准库（NAS 自带 python3 够用了），重活交给远程或编译出来的 C
8. ✅ SSH 远程命令里别用带引号的 `~`；`pkill -f` 加 `$` 锚定
9. ✅ 远程管理类应用，工作模式记得停休眠计时器

### 核心经验

- **GPU 是排他资源**：多 AI 服务共存的机器，一定要有个"模式切换"层，而不是让它们开机互殴
- **状态协议要结构化**：给 shell 脚本加个 `--json` 输出，上层 app 的解析成本几乎为零
- **远程管理最怕"友军伤害"**：自己的节能策略会背刺长任务，切换工具和电源策略必须联动
- 飞牛应用的核心是**生命周期脚本 + 向导 + Web 面板**三件套，后端喜欢用啥用啥（这里甚至没用任何 pip 包）
